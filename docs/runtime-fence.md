Adopted source: joelhooks/rat-stack, MIT, commit `f396f76f8ced98d4bc4d510ae8457142cd66db81`. `scripts/vcs-command-policy.js` and its declaration are copied unchanged. `scripts/landmines/{baseline,finding}.ts` retain the donor exact-budget implementation (baseline location adapted). The root Lefthook check-then-test sequence and frozen/offline/lockfile-only install policy follow donor root configuration. Repository `LICENSE` and fence adoption records retain donor license attribution.

`check-landmines.mjs` executes the real installed Oxlint plugin over every existing package source/test directory, scripts and the compiler parity test, matching the root lint scope. It compares every selected finding against exact path, owner, option and value signatures. The target started empty; its eight existing explicit test deadlines were recorded separately with process/property-run rationales. Expanding the scope introduced no further allowances. Stale allowances fail. CI sets an exact PR base SHA; added budgets cannot recycle a base reason. These are test-run deadlines, not retries. The dedicated budget config loads only the selected Landmines rules so its structured output contains budget findings; the full root linter independently enforces all other rule families.

The environment schema admits optional `LANDMINES_BASE` for CI budget comparison and `AU_TRACE` for the CLI's local JSONL span destination. The CLI receives catalog location through an argument and does not need donor service credentials. Test harness overrides and standard process environment are not application configuration.

Lefthook runs `pnpm check` then `pnpm test`. GitHub CI runs frozen install, lock check, environment admission, check, test, build, cold consumer and original Python tests independently of local hooks. `operational.test.mjs` exercises bypass spellings and valid neighboring commands against the copied policy, plus new/stale/recycled budget failures. The native Codex project registration and stdin adapter are documented in `codex-hook.md`; actual adapter subprocess tests are in the root test gate. Host interception remains unproven until the principal reviews and trusts that project hook through `/hooks`. No stored trust or approval bypass is installed. A Claude-specific donor hook would not establish Codex coverage.

No Turbo runner or cached build consumer exists in this runtime. Turbo input hashing and cache reporting are not applicable here; there is no fabricated cache proof. If a cached build is introduced, donor input-audit and honest-summary implementations must travel with that actual graph.

`pack:runtime` invokes the canonical `scripts/pack-runtime.mjs` builder. It packs nine public packages in a fixed order, hashes their actual tarball bytes with SHA-256 and writes `manifest.json` with `{schemaVersion:1,release,packages:[{file,sha256}],installFiles:[{file,sha256}]}`. The required install files are a private distribution `package.json` and its actual npm-generated `package-lock.json`. The distribution manifest has only production dependencies on the nine local tarball basenames; lock generation disables scripts and excludes development installation. The installer copies hash-checked artifacts and these install files into its immutable release directory, then runs `npm ci`, so the consumer uses the distributed dependency lock rather than resolving transitive ranges again. The checkout's pnpm lock alone would not protect a consumer installation.

An explicit builder `--out DIRECTORY` must be empty; without one it creates an OS temporary directory and prints its location. Artifacts and manifest are made read-only, and a nonempty output cannot be silently replaced. Package `files` declarations select distribution output and public documentation; no house state is packaged. Byte determinism and actual locked installation must be verified by comparing two builds and running the cold path at the same checked source before publication.

The cold-consumer script calls that builder, then invokes the actual `tools/runtime.py install --release DIRECTORY --house DIRECTORY` installer. It admits the installer's JSON receipt and uses its selected Node executable and CLI entry. From an unrelated temporary directory it copies the actual catalog fixture and proves a known workflow plus typed `not-found` failure for an absent workflow. It removes its temporary consumer afterwards. It does not require the site checkout or deploy anything.
