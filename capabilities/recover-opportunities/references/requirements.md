# Recurring requirements — draft 1

These stable local names identify requirements within this skill, not records asserted to exist in any institutional graph. Their definitions are the contract for this draft. They specify observable information/actions, not vendors. Checks are performed with the available tools and retained as observations, not attested by package installation.

| Need | Requires | Acceptable evidence of a usable implementation | If unavailable |
| --- | --- | --- | --- |
| source-read | Relevant estimate and conversation locations; selected business/account; authorized reading | Read an actual estimate and its relevant history from the identified business, preserving identities, versions, dates, coverage and source references. Partial exports remain explicitly partial. | Identify the missing source/account/read action. Work with available evidence without inferring absent history. |
| fit-judgment | source-read; actual service/territory/pricing/capacity boundaries needed by this case | Source-backed applicable rules and current capacity, with unresolved owner facts identified; distinguish whether a project is unsuitable from whether suitability is unknown. | Seek the specific missing fact/decision. Do not use missing economics to assert profitability. |
| proposal-work | source-read; fit-judgment for substantive commercial recommendations; document read/write ability | Open the actual proposal version, produce a usable reviewed revision/explanation, retain the original and show what changed. | Prepare the analysis or requested draft in an available format; report any inability to update the actual quoting system. |
| conversation-act | source-read; recipient/sender identity; current action authority; selected communication implementation | Inspect actual history and intended target. For sending, obtain sufficient scope and verify the real tool's recorded result. A read/draft demonstration does not prove sending works. | Draft only, or wait for exact access/authority. Do not send a test message to prove readiness without authorization. |
| commitment-act | source-read; relevant fit-judgment; current availability; authority to make the particular commitment | Verify the right calendar/capacity and record an authorized commitment through its actual working surface, then read it back. | Offer a proposal or internal handoff, clearly unconfirmed; ask for the missing decision/access. |
| carry-work | Writable native case/task record or suitable local record; next-action owner; trigger if recurring operation is requested | Save and reopen current case state; verify a real trigger if activated. Fresh-agent continuation is evaluated separately from simply writing a handover. | Retain explicit pending state and a truthful return instruction. Do not claim autonomous recurrence. |

Information-source alternatives include CRM and inbox, or spreadsheet/PDF estimates and messages. Read tools can be connectors, browser control or direct files. They must supply the meaning and scope needed by the branch; reading only a status column is not equivalent to reading relevant conversations.

Order only the active branch's dependencies. Reconciliation requires source-read, not send permission. A proposal draft does not require commitment-act. A live booking does. carry-work applies whenever a branch leaves pending responsibility. A dependency cycle or a missing definition is a package defect; name it rather than inventing readiness.
