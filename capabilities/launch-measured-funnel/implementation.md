# Use the existing business implementation

Read SKILL.md first. Acquire the pinned bundle through IMPLEMENTATIONS.md. Read its
`packages/launch/README.md`, source schemas and example JSON before writing the
owner-specific inputs. Those files travel with the implementation. Do not require
access to a sibling checkout or substitute the example business for the owner.

## Fit before provider work

Inspect only the tools, accounts and sources this outcome needs. Keep configuration
and useful operating state where the existing tools expect them. Do not make the
person maintain a capability ledger or turn useful work into a reporting exercise.
Ask a concrete question when the person's decision or access is actually needed.

The initial connected provider path is the funnel runtime below. Hosted commerce
can be exercised locally, but its provider entry still assumes historical fixed
deployment names. Do not run hosted `business-deploy` in a new owner's account
until that isolation gap is repaired. Never print credentials or copy login state.
If a needed service is unavailable, continue independent work and explain what is
missing. Do not silently switch the promised result to a simulation.

## Compose the owner's business

The `spell` entry accepts `launch SENTENCE --drafts FILE --copy FILE`. The files are
agent-authored inputs admitted by the existing Offer and Copy schemas. Read their
schemas and examples, prepare the actual offer and persuasive work from owner
sources, and retain them separately from original material. No model API or model
choice is embedded in this release. Do not claim the implementation itself wrote
the copy. Use the principal's model preference.

First run without `--stage` to exercise the local launch saga. Inspect refusals,
repair the actual draft and rerun. `--yes` represents authorization for that exact
invocation, never a substitute for the owner's decision. In a fictional test retain
the explicit fixture authority; it does not authorize real business publication.

The bundle includes the historical hosted command sequence for engineering work.
Its presence does not qualify new-owner provider execution. Prefer the functioning
funnel path for intake and useful free delivery while that gap remains.

For a future qualified hosted path, verify public pages, exact price, test checkout,
order, inbox, actual delivery, reporting and an authorized test refund. A durable
welcome message does not constitute delivery of an entire course or service.

Leave only the information needed to use and continue the result: where it lives,
what works, what is waiting, and the next useful action. Qualification captures the
full native run separately; the recipient is not assigned a second reporting job.

## Funnel runtime

Use `funnel` for an existing Books-format funnel with slots/images and declared
forms. Read the included `packages/funnel-deploy/README.md` and schema/fixtures.
Prepare the source and run `deploy --local --directory DIR --state NEW_DIR --json`.
Keep the process alive, exercise the actual form, and use `results --state DIR --json`
to read persisted intake and tracking. `teardown --state DIR --json` stops that local
runtime while retaining its data. A public preview has separate configuration and
authority requirements described in the included package docs. It cannot charge
or send email. The runtime is useful for deployed intake/measurement; use hosted
commerce for the implemented payment/order path.
